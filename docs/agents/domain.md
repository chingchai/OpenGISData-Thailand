# Domain docs

## Layout

Use one root `GLOSSARY.md` and root `docs/adr/` directory.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the work.
If `GLOSSARY-MAP.md` exists, follow it to relevant context glossaries.

When these documents are absent, proceed silently.
The domain-modeling skill creates them as terms and decisions are resolved.

## Vocabulary and decisions

Use glossary terms in issues, proposals, hypotheses, and tests.
Note missing concepts for domain-modeling when appropriate.

Explicitly flag proposals that contradict an existing ADR.
Name the ADR and explain why the decision should be reconsidered.
